# УП.04 — День 09. Docker Compose

## Цель работы

Подготовить существующего ИИ-агента к запуску через Docker Compose, проверить конфигурацию, собрать образ и выполнить два запуска консольного приложения.

## Используемое окружение

Docker: 29.10.0 build fdd4b8e
Docker Compose: v5.8.0
Операционная система: Ubuntu Server 24.04.
Проект: ИИ-помощник по созданию и психологическому анализу персонажей.
Каталог проекта: `УП01/AI-Agent`.

Назначение параметров:

| Параметр | Назначение |
|---|---|
| `services` | Список сервисов Compose |
| `agent` | Имя сервиса |
| `build: .` | Сборка образа по Dockerfile из текущей папки |
| `image: my-ai-agent:1.0` | Имя и тег образа |
| `env_file: - .env` | Передача переменных окружения из локального файла `.env` |
| `stdin_open: true` | Оставляет открытым стандартный поток ввода |
| `tty: true` | Подключает псевдотерминал для интерактивной работы |

## Проверка конфигурации, сборка и запуск

Команды выполняются из каталога `УП01/AI-Agent`

Проверка конфигурации без вывода значений переменных:

```bash
sudo docker compose config --quiet
```

Сборка образа:

```bash
sudo docker compose build
```

Первый запуск агента:

```bash
sudo docker compose run --rm agent
```

После запуска был введён запрос по теме ИИ-помощника. Программа запустилась в контейнере и вывела ответ. Для завершения использована штатная команда выхода приложения.

Повторный запуск:

```bash
sudo docker compose run --rm agent
```

Во втором запуске был введён другой запрос. Агент снова запустился и обработал ввод.

Проверка состояния контейнеров и образа:

```bash
sudo docker compose ps -a
sudo docker compose images
sudo docker images my-ai-agent
```

После запуска с параметром `--rm` контейнер удаляется при завершении программы. Поэтому список контейнеров может быть пустым. Собранный образ при этом сохраняется.

## Образ и контейнер

**Образ Docker** — подготовленный шаблон приложения со средой выполнения и установленными зависимостями. Он сохраняется и используется для создания контейнеров.

**Контейнер** — отдельный экземпляр образа, в котором непосредственно выполняется приложение. Контейнер можно создать, запустить и удалить, не удаляя сам образ.

## Фактические результаты двух запусков

| Запуск | Действие | Фактический результат | Статус |
|---|---|---|---|
| 1 | Запуск агента и ввод первого запроса | Агент запустился в контейнере и вывел ответ на запрос | Пройдено |
| 2 | Повторный запуск и ввод другого запроса | Новый запуск прошёл, агент обработал запрос и вывел ответ | Пройдено |

## Вывод

В ходе девятого дня для существующего ИИ-агента подготовлен файл `compose.yaml`. Конфигурация проверена, Docker-образ собран, агент запущен через Docker Compose и успешно проверен повторным запуском.

Запуск консольного агента выполняется командой `sudo docker compose run --rm agent`. Такой способ подходит приложению, которому необходим пользовательский ввод в терминале.
